- **Fix — Restore 400 (2026-05-05).** `POST /v1/products/:id/restore` from the web app was returning 400 instead of restoring. Root cause: `apiFetch` (and `apiFetchWithMeta`) in `apps/web/src/lib/api/client.ts` set `Content-Type: application/json` on every request, even when no body was being sent. Fastify's default JSON parser then rejects the empty body with `FST_ERR_CTP_EMPTY_JSON_BODY` ("Body cannot be empty when content-type is set to 'application/json'") on methods that run the body parser (POST/PUT/PATCH).
